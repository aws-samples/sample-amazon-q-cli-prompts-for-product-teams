Overview

The Product Team's Tool Chest transforms AI coding assistants into comprehensive product development partners. Using steering files, the toolkit guides AI through a complete workflow from market research to interactive prototype.

What is Kiro?

Kiro is an agentic AI IDE and CLI that helps you go from prototype to production with spec-driven development. It transforms natural language prompts into structured specifications, working code, documentation, and tests.

Why Kiro?

Steering Files

Markdown files in .kiro/steering/ that configure how AI agents interact with your project—coding standards, workflows, and constraints load automatically.

Agent Hooks

Event-driven automation that triggers on file saves, commands, or custom events. Run validators, formatters, or workflows automatically.

Spec-Driven Development

Converts prompts into structured requirements and implementation plans with discrete tasks. Analyzes your codebase to recommend architecture.

The Workflow

1

Deep Market Research

6 parallel research dimensions with 120+ sources, quality gates, policy/risk/opportunity analysis, and a Challenge Check that stress-tests assumptions before proceeding.

2

PRFAQ

Amazon-style Working Backwards with Challenge Check — strengthens problem framing and ensures FAQ addresses genuine skepticism, not softballs.

3

PRD

Implementation-ready requirements with current-year technology research, inline SVG architecture diagrams, and user stories in EARS format.

4

Prototype

Interactive HTML with Chart.js visualizations, realistic state persistence, adversarial Bug Hunt, and modular screen architecture.

All Outputs are Standalone HTML

Every document is a self-contained HTML file that opens directly in any browser. No build step, no server, and no CDN-loaded scripts — any library (e.g. Chart.js) is downloaded locally at build time; the only external reference is Google Fonts CSS, which degrades gracefully offline. Share with stakeholders by simply sending the files.

Setup Guide

Important: Hidden Files

The .kiro and .cursorrules files/folders are hidden (they start with a dot). You won't see them in Finder or File Explorer by default.

To show hidden files:

  • macOS Finder: Press Cmd + Shift + . (period)
  • Windows Explorer: View → Show → Hidden items
  • VS Code: Hidden files are visible by default in the file tree
  • Terminal: Use ls -la to see all files including hidden ones

Option A: Kiro (Recommended)

The fastest way to get started. Kiro natively supports steering files and agent hooks. Available as both a desktop IDE and CLI.

Step 1: Install Kiro

Desktop IDE (GUI):

  1. Visit kiro.dev
  2. Download the installer for your platform (macOS or Linux)
  3. Run the installer and follow the prompts

Command Line (CLI):

# macOS / Linux curl -fsSL https://cli.kiro.dev/install | bash

Step 2: Copy Files to Your Project

Choose your preferred method to copy the toolkit files:

Method A: Using Finder/File Explorer (GUI)

  1. Show hidden files first:
    • macOS: Press Cmd + Shift + . in Finder
    • Windows: View → Show → Hidden items
  2. Open this toolkit folder in Finder/Explorer
  3. You should now see the .kiro folder (it will appear slightly faded)
  4. Copy the entire .kiro folder to your project's root directory
  5. Create a documents folder in your project (for outputs)

Method B: Using Terminal (CLI)

# Navigate to your project cd /path/to/your-project # Copy the entire .kiro folder (includes steering files and hooks) cp -r /path/to/toolkit/.kiro . # Create the documents folder for outputs mkdir -p documents # Verify the files were copied ls -la .kiro/ # You should see: steering/ and hooks.json

What gets copied:

  • .kiro/steering/ — Product workflow, design standards, phase guides
  • .kiro/hooks.json — Validation hooks and analysis agents

Step 3: Open in Kiro

Using the Desktop IDE:

  1. Launch Kiro from your Applications folder
  2. Click File → Open Folder (or Cmd/Ctrl + O)
  3. Select your project folder
  4. The steering files load automatically — you'll see them in the .kiro/steering/ folder in the file tree

Using the CLI:

# Navigate to your project and start Kiro cd /path/to/your-project kiro

Step 4: Describe Your Product

In the Kiro chat panel, simply describe your product idea. For example:

"I want to build a fitness tracking app for teenagers that uses AI to create personalized workout plans."

The steering files automatically guide the AI through the workflow: Deep Market Research → PRFAQ → PRD → Prototype.

Option B: Claude Code / Cursor

A complete workflow guide designed specifically for Claude Code and Cursor users.

Step 1: Copy Files to Your Project

Choose your preferred method to copy the toolkit files:

Method A: Using Finder/File Explorer (GUI)

  1. Show hidden files first:
    • macOS: Press Cmd + Shift + . in Finder
    • Windows: View → Show → Hidden items
  2. Open this toolkit folder in Finder/Explorer
  3. Copy the prompts folder to your project
  4. Copy CLAUDE.md to your project root (for Claude Code)
  5. Copy .cursorrules to your project root (for Cursor — it will appear faded)
  6. Copy the .claude folder to your project root (Claude Code: native subagents, skills, and validation hooks)
  7. Create a documents folder in your project (for outputs)

Method B: Using Terminal (CLI)

# Navigate to your project cd /path/to/your-project # Copy the prompts folder cp -r /path/to/toolkit/prompts . # For Claude Code: copy CLAUDE.md (auto-loads) cp /path/to/toolkit/CLAUDE.md . # For Claude Code: copy the native layer (subagents, skills, validation hooks) cp -r /path/to/toolkit/.claude . # For Cursor: copy .cursorrules (hidden file, auto-loads) cp /path/to/toolkit/.cursorrules . # Create the documents folder for outputs mkdir -p documents # Verify the files were copied ls -la # You should see: CLAUDE.md, .cursorrules, prompts/

What gets copied:

  • CLAUDE.md — Auto-loaded by Claude Code
  • .cursorrules — Auto-loaded by Cursor (hidden file)
  • prompts/ — Phase guides and workflow documentation

Step 2: Open Your Project

For Cursor (GUI):

  1. Launch Cursor from your Applications folder
  2. Click File → Open Folder (or Cmd/Ctrl + O)
  3. Select your project folder
  4. The .cursorrules file loads automatically in the background

For Claude Code (CLI):

# Navigate to your project and start Claude Code cd /path/to/your-project claude

The CLAUDE.md file loads automatically when Claude Code starts.

Step 3: Describe Your Product

In the chat panel (Cursor) or terminal (Claude Code), describe your product idea. For example:

"I want to build a fitness tracking app for teenagers that uses AI to create personalized workout plans."

The AI will automatically begin the Discovery phase and guide you through the workflow (4 phases, plus an AI Framing phase for AI/ML products).

Differences from Kiro

  • Same phase workflow including market research
  • Load phase guides manually (vs. Kiro's automatic steering)
  • Narrower automatic validation — Claude Code runs an advisory JS-syntax gate on Screen files and an SVG check on PRDs (.claude/settings.json); Kiro's 17 hooks cover more

The Workflow

Each phase produces validated HTML documents. The workflow includes automatic validation checkpoints, Challenge Checks that stress-test assumptions, and a Bug Hunt that finds and fixes interactive bugs before presenting to you.

Phase 1: Deep Market Research

AI researches across 6 parallel dimensions:

  • Industry Landscape — market sizing, growth, disruption
  • Competitive Intelligence — 5-7 competitors with pricing, strategy, gaps
  • Customer & Persona Deep Dive — pain points, workflow friction, buying behavior
  • Technology Radar — emerging tech mapped to AWS services
  • Adjacent Innovation — startups, new product launches
  • Policy, Risk & Opportunity — legislation, backlash, lawsuits, blue ocean signals

Quality gate: 120+ sources minimum, 15+ per dimension. Challenge Check stress-tests findings before proceeding.

Output: MarketResearch_[Product]_[Date].html

Validation Requirements

  • TAM/SAM/SOM with actual dollar figures and sources
  • At least 3 competitors with real pricing data
  • Pain points must be specific, not generic
  • No placeholder text (TBD, TODO, [insert])

Phase 1b: AI Framing (Optional)

Only for AI/ML products. Defines ML problem type, input/output schemas, success metrics, and training data requirements.

Phase 2: PRFAQ

Amazon-style Working Backwards documentation:

  • Press Release written as if product already launched
  • FAQ addressing customer and business questions
  • Incorporates market research findings

Output: PRFAQ_[Product]_[Date].html

Phase 3: PRD

Implementation-ready specification:

  • User personas with detailed profiles
  • Requirements in EARS syntax (When/The/Shall format)
  • User stories with acceptance criteria
  • Success metrics and business model

Output: PRD_[Product]_[Date].html + Kiro spec files

AWS-Native Architecture

As an AWS-provided toolkit, designs prefer AWS services for enterprise-grade scalability, security, and compliance:

Compute: Lambda, ECS, EC2, App Runner • Database: DynamoDB, Aurora, RDS • Generative AI: Amazon Bedrock, Bedrock AgentCore, Amazon Q • Storage: S3, EFS • API: API Gateway, AppSync • Auth: Cognito

Amazon Bedrock provides access to foundation models from Amazon (Nova) and third-party providers (Anthropic Claude, Meta Llama, and more).

Phase 4: Prototype

Interactive HTML prototype with:

  • Modular file structure (NOT a single monolithic file)
  • Distinctive visual design (no generic "AI slop")
  • Working navigation between screens
  • Form validation and feedback
  • Responsive layouts (desktop, tablet, mobile)
  • Realistic data (no Lorem ipsum)

The toolkit enforces distinctive design to avoid generic "AI slop" aesthetics.

Gradients, shadows, and depth

Best Practices

Trust the Validation

The workflow won't proceed until validation passes. If you're tempted to skip validation, that's a sign the work needs improvement.

Provide Rich Context

The more real data you provide (team members, customer info, brand guidelines), the better the output quality.

Don't Skip Deep Market Research

The PRFAQ and PRD are dramatically better when grounded in real competitive data. Deep market research with 120+ sources is mandatory and cannot be skipped.

Modular Prototypes Only

Never accept a single monolithic HTML file. The prototype must be split into separate screen files with a shared design system.
